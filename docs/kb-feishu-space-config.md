## 1. 成员组（管理后台 → 组织架构 → 用户组）

| 成员组 | 成员 | 用途 |
|---|---|---|
| `kb-editors` | IT + 各部门文档编辑者 | 公开区编辑 |
| `kb-dept-{部门}` × N | 各部门全员（可与飞书部门同步） | 部门区可见性 |
| `kb-sensitive` | 白名单（IT 负责人 + 资产/安全负责人） | 敏感区唯一入口 |

## 2. 知识空间创建（wiki 管理后台）

| 空间 | 权限配置 |
|---|---|
| **公开区**（如「公司知识库」） | 全员可读（组织内可见）；编辑仅 `kb-editors`；管理员=IT |
| **部门区**（每部门一个空间，或单空间按顶层节点分部门） | 空间成员=`kb-dept-{部门}`；空间管理员=部门负责人；**敏感子目录断开继承**单独授权 |
| **敏感区**（独立空间「受限资料」） | 成员仅 `kb-sensitive`；关闭「组织内可见」；开水印 + 禁下载/复制/打印（商业版）；开审计日志 |

单空间多部门 vs 每部门一空间：部门 ≤5 用单空间+顶层节点分部门（管理简单）；部门多或有跨部门隔离硬要求则每部门一空间。默认建议后者（贴合「不同部门只能看对应文档」）。

## 3. 权限矩阵映射（设计稿 → 飞书配置项）

| 设计稿角色 | 飞书实现 |
|---|---|
| KB 管理员 | 各空间「管理员」+ wiki 管理后台权限 |
| 空间管理员（部门负责人） | 本部门空间管理员；公开区编辑者（`kb-editors`） |
| 编辑者 | 空间「可编辑」成员 |
| 成员 | 空间「可阅读」成员 |
| 敏感区白名单 | `kb-sensitive` 成员组，逐人审批加入，加入/移出记录留痕 |
